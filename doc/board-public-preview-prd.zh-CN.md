# Board 公开预览 产品需求文档

[English](./board-public-preview-prd.md)

> 实现基线：Workavera `0.1.1`。

## 1. 产品目的

Board 公开预览让项目 Owner 把一个项目发布成不可猜测的链接，任何人无需登录即可打开，
一眼看清这是什么项目、总共多少任务、各状态各多少、团队有谁，以及每个任务哪一天开始、
持续到哪一天、每一天分别在做什么、哪些已经完成。

它是 Docs 公开分享（`/s/{slug}`）在 Board 上的对应能力：同样由创建者掌控、同样是不可
枚举的链接、同样在撤销或过期后立即失效，但展示的不是一份快照，而是项目此刻的真实进度。

为了表达"持续到哪一天"，本功能给任务增加可选的开始日期。这是一处超出公开预览本身的数据
模型变化，第 6 节单独说明它的完整影响面。

## 2. 目标

- 给任务增加可选开始日期，使任务成为一段时间区间而不只是一个截止时间点。
- 项目 Owner 可以发布项目、设置可选过期时间、复制链接、随时撤销。
- 匿名访问者在 `/p/{slug}` 打开一个只读的项目预览页，不需要账号。
- 页面顶部一屏之内给出项目名称、描述、日期跨度、任务总数和各状态任务数。
- 页面列出项目参与者（Owner 与成员）的名称与头像。
- 主体是日历时间线：任务按开始日到截止日横跨若干天，并可按天读出当天在做什么。
- 任务以与 Board 内一致的任务卡片呈现，点击展开只读详情。
- 任务关联的文档：已公开的直接跳转到它的公开链接；未公开的明确提示作者未公开。
- 页面提供刷新按钮，让访问者主动取得项目最新进度。

## 3. 非目标

- 匿名访问者的任何写入：评论、认领、拖拽、编辑、导出。
- 公开页面的实时推送（PocketBase realtime 需要认证，匿名订阅不在范围内）。
- 在时间线上拖拽调整任务日期，或任务之间的依赖、里程碑、关键路径。
- 可枚举的公开项目目录、SEO 收录、社交卡片预览图。
- 链接访问密码、访问次数统计、访客名单，或关闭整个实例分享能力的总开关。
- 项目级之外的分享粒度（按状态、按成员、按标签分享子集）。
- 归档项目的公开链接，以及在公开页展示归档任务、活动日志、项目设置。

## 4. 核心规则

1. 只有项目 Owner 可以发布、设置过期、撤销链接，与归档和删除项目的权限一致；Admin、
   Member、Viewer 都不带来任何分享权限。
2. 一个项目最多一条分享记录。撤销即删除记录，因此再次发布会签发新的 slug，旧链接不会
   复活。
3. 公开页面反映项目**当前**状态，不固定快照。发布之后新增或改动的任务会立即对外可见，
   这是刻意的：项目进度的价值在于实时。Owner 靠撤销与过期控制暴露窗口。
4. 链接在过期、被撤销，或项目被归档、删除的那一刻立即失效。这几种情况返回完全相同的
   响应，链接不透露究竟发生了哪一种。
5. 公开页面只呈现未归档任务。归档任务、活动日志、项目偏好、任务负责人、成员角色、成员
   邮箱与任何用户身份标识都不出服务器。团队只在成员区以名称与头像整体呈现。
6. 任务关联文档只暴露标题，以及"是否有一条当前有效的公开链接"。有效时给出该文档的
   slug，无效时不给任何 ID，页面提示作者未公开。
7. 公开接口不接受任何认证，也不因访问者恰好登录而返回更多内容：Owner 与陌生访客看到的
   完全一致。
8. 发布、改期、撤销都不修改项目与任务，也不产生活动记录之外的任何数据变化。
9. 任务的 `start_date` 可选。设置时必须早于或等于 `due_date`，服务端在共享命令层与
   PocketBase 写入 Hook 上一并校验，与既有的跨项目关系校验同一层。

## 5. 数据模型

### `board_project_shares`（新增）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `project` | relation → board_projects | 必填、唯一、级联删除 |
| `slug` | text | 唯一的 22 位小写字母数字公开标识 |
| `expires` | date | 可选；为空表示链接不过期 |
| `created_by` | relation → users | 执行发布的项目 Owner |
| `created`、`updated` | autodate | 记录时间戳 |

与 `doc_shares` 同构，只是不保存 `revision`——公开页面跟随项目当前状态，没有需要固定的
快照。分享独立成表，使发布、改期和撤销都不触碰项目和任务记录。

Owner 通过 PocketBase list/view 规则读取自己项目的分享（`@request.auth.id != "" &&
project.owner = @request.auth.id`）；所有写入都走 Board 分享接口，客户端不能自己指定
slug。`project` 与 `slug` 各建唯一索引。

### `board_tasks.start_date`（新增字段）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `start_date` | date | 可选开始日期；设置时不得晚于 `due_date` |

其余 Board 集合与 `docs` / `doc_shares` 均保持不变。

## 6. 任务开始日期的影响面

`start_date` 是本次唯一的既有数据变更，它会穿过整条任务链路：

- **迁移**：新增可选日期字段并附回滚，配套迁移测试。历史任务字段为空，行为与今天一致。
- **服务端校验**：`internal/board` 的任务写入路径校验 `start_date <= due_date`，两端任一
  为空都合法。
- **Board UI**：任务详情表单在截止日期旁增加开始日期选择器，并对倒置的日期给出即时反馈。
  Board 内的任务卡片保持现状，只显示截止日期，避免看板列变拥挤。
- **Assistant 工具**：`board_create_task` 与 `board_update_task` 增加 `startDate` 入参，
  沿用现有 patch 语义——空字符串清除开始日期。
- **移动端**：Android 与 iOS 客户端在各自仓库里跟进，不属于本次范围。它们不识别新字段时
  只是不显示，写入任务也不会清除它。

任务在时间线上的区间由两个日期共同决定：

| `start_date` | `due_date` | 时间线表现 |
| --- | --- | --- |
| 有 | 有 | 从开始日横跨到截止日的条带 |
| 无 | 有 | 截止日当天的单日条带 |
| 有 | 无 | 开始日当天的单日条带 |
| 无 | 无 | 不进入时间线，归入 `Unscheduled` |

## 7. 公开页面体验

页面在认证外壳之外的 `/p/{slug}` 打开，与 `/s/{slug}` 一样不加应用导航、侧栏和账号入口。
浏览器标签页标题为项目名称。文案沿用现有界面的英文风格。

日期默认按英文格式呈现，链接加上 `?lang=zh` 后改为中文格式：`Aug 13 – Sep 6` 变成
`8月13日 – 9月6日`，`Thursday, Aug 13` 变成 `8月13日 星期四`，月份轴变成 `2026年9月`，
相对时间变成 `更新于 不到 1 分钟前`。中文日期不是把英文格式逐词翻译，而是各有各的顺序和
分隔符，因此两种语言各自定义 pattern。参数只作用于日期与紧挨着日期的标签，界面其余文案
保持不变；任何以 `zh` 开头的取值都视为中文，其余一律回到默认。

### 顶部概览

- 项目名称与描述。
- 日期跨度，例如 `Aug 3 – Sep 12`，跨年时带年份；项目没有任何带日期的任务时不显示。
- 任务总数，以及按状态的计数芯片，芯片使用状态自己的颜色并按 `sort_order` 排列，
  例如 `Todo 4 · In Progress 3 · Done 12`。
- 完成度：`completed` 类别状态的任务数占比，一条细进度条。
- 刷新按钮：图标按钮，点击重新拉取整份数据，进行中显示旋转态；旁边显示 `Updated
  2 minutes ago` 的相对时间。连续点击有一秒节流，避免打空转。
- 进度条以上的部分在向下滚动时固定在页面顶部，访问者读到时间线深处也知道自己在看哪个
  项目、还剩多少。进度条本身随页面滚走。粘性元素的活动范围受限于父元素，所以这块必须是
  页面主列的直接子元素，不能包在自己的容器里。
- 这块的高度取决于项目描述的长短，因此它用 `ResizeObserver` 把实测高度写进
  `--public-header-height`，按天层的日期头据此停靠在它正下方，而不是假定一个高度。

### 项目成员

Owner 与成员合并为一行头像加名称，Owner 排在最前并标注 `Owner`。不显示角色、邮箱或任何
其他联系方式，也不显示谁负责哪条任务。头像由分享自己的代理接口按成员在列表中的序号提供，
因此连用户 ID 都不出现在响应里。

### 日历时间线

时间线是页面主体，分两层，共享同一条日期轴的起止范围（项目最早开始日到最晚截止日）。

**跨度层**：横向的日期轴加任务条带。任务按所属状态分组，组内按开始日排序后做 lane
packing——同一状态里时间不重叠的任务共用一行，因此高度取决于并行度而不是任务总数，几十条
任务也能在一屏内看完，左侧的状态分组本身又把"各状态各多少"直接摊开。条带以所属状态的
颜色填充，条上显示任务标题，已完成的条带减淡并前置完成勾选标记。今天有一条竖线贯穿。
跨度超过一屏时横向滚动，首次加载滚动到今天；跨度很长时日期轴按周聚合刻度，条带位置不变。
点击条带打开任务详情。

**按天层**：跨度层下方是按天从早到晚的分组列表，回答"这一天在做什么"。

- 每个日期一个粘性日期头：星期几、日期、当天进行中的任务数，以及 `3 of 5 done`。日期头
  停靠在顶部概览下沿，不与它重叠。
- 一个任务出现在它区间覆盖的每一天：开始日显示完整任务卡片，后续各天显示紧凑条目
  （标题、状态色点、`Day 2 of 5`）。
- 一天超过六条任务时只展开前六条，其余收在 `+3 more` 后面，点击展开、再点收起。六条在宽
  屏正好是两行，够读完忙碌的一天；否则单独一天就会把后面的日期挤到很远的下方。
  `Unscheduled` 用同一规则。
- 今天的分组高亮。没有任务的日期折叠为一条细的空白刻度，保持时间连续又不撑长页面。
- `Unscheduled` 分组固定在最后，收纳既无开始日也无截止日的任务。
- 已完成任务的卡片带完成表现：标题减淡、前置完成勾选标记。
- 窄屏隐藏跨度层，只保留按天层，卡片单列排布。

### 任务卡片

复用 Board 的任务卡片视觉：标签色块、标题、描述摘要、优先级、日期、关联文档数。落地方式
是把 `todo-card.tsx` 中的展示部分抽成一个纯展示组件，接收已解析好的标签与优先级作为
props，并支持隐藏负责人；Board 内的 `TodoCard` 保留拖拽与归档交互并复用它，公开页面直接
使用它，两边不再各写一份卡片。公开页面的卡片不可拖拽、没有归档按钮、不显示负责人，日期
显示为区间（`Aug 3 – Aug 7`）或单日。

### 任务详情

点击卡片或条带打开只读弹窗：标题、完整描述、所属状态、优先级、标签、开始与截止日期，
以及关联文档列表。不显示负责人、创建者和活动记录。

- 已公开且当前有效的文档：条目可点击，在新标签页打开 `/s/{doc-slug}`。
- 其余文档：条目灰显、不可点击，附 `Not shared by the author` 说明。

### 链接不可用

与公开文档页一致：只说明链接不可用，可能已过期、被撤销或从未存在，不区分原因，也不透露
项目是否存在。

### 实现方式

时间线不引入新依赖，用 CSS Grid 加已有的 `date-fns` 实现。剥去交互之后它是一个纯布局
问题：把任务的 `[开始日, 截止日]` 映射成网格列跨度，`grid-column: start / span n` 正好
表达这件事，颜色、圆角和暗色主题全部沿用现有 Tailwind token，与 Board 视觉自动一致。

现成的日历与甘特库都不合适：FullCalendar 的时间轴视图是商业授权，免费版给不出这个形态；
react-big-calendar 是"周/日程"心智，画不出项目跨度总览；gantt-task-react 一类为可拖拽
编辑的甘特设计，而公开页面只读，它们的内联样式又难以跟随主题。公开页是匿名首屏，省下的
体积也有实际价值。`react-day-picker`（`ui/calendar`）继续只做日期选择，分享对话框的过期
日期直接复用 `ui/date-picker`。

- 日期轴由 `eachDayOfInterval` 生成；条带的列起点是 `differenceInCalendarDays(任务开始,
  跨度开始) + 1`，跨度是两个日期相差的天数加一。
- 列宽随跨度分档：60 天以内每日 48px 并在条带内显示标题；61 至 180 天收窄到 24px，标题
  改由 tooltip 给出；超过 180 天改为每列一周，用 `differenceInCalendarWeeks` 定位。
- 日期轴分月、日两行并粘在顶部，周末列铺一层浅背景，今天是一条绝对定位的竖线，首次加载
  把它滚动到视口靠左三分之一处。
- 跨度计算、列宽分档和 lane packing 放在 `frontend/src/lib/timeline.ts` 里做成纯函数，
  两种语言的日期 pattern 和格式化放在 `frontend/src/lib/date-format.ts`。

## 8. 发布体验

- 入口是项目标题行右侧的一个分享图标，与复制项目引用、归档任务的图标排在一起，仅项目
  Owner 可见。已经有链接时图标显示为绿色，Board 上一眼就能看出哪些项目已经对外公开；
  为此分享状态在项目渲染时就读取，而不是等对话框打开。
- 分享对话框负责：创建链接、复制链接、在新标签页打开链接、选择日期语言、设置或清除过期
  时间、撤销。
- 链接旁的复选框控制是否附加 `?lang=zh`，勾选后复制和打开都带上它，既说明了参数本身，
  也省去手工拼接。参数只影响日期格式，因此属于分发出去的链接而不属于分享记录。
- 对话框明确说明公开页面反映项目当前进度，并列出会对外可见的内容（任务标题与描述、状态、
  标签、日期、成员名称与头像）与不会对外可见的内容（归档任务、活动记录、任务负责人、
  成员邮箱与角色）。
- 撤销说明旧链接不会再恢复。
- 对话框同时说明归档或删除项目会让链接立即失效，因为归档本身是一步到位的操作，提示留在
  分享入口比拦在归档路径上更合适。

## 9. HTTP API

已认证接口（`apis.RequireAuth("users")`，仅项目 Owner）：

- `GET /api/board/projects/{id}/share`
- `POST /api/board/projects/{id}/share`，接受可选 `expires`
- `DELETE /api/board/projects/{id}/share`

匿名接口：

- `GET /api/public/board/{slug}`
- `GET /api/public/board/{slug}/avatars/{index}`

匿名接口是访问者唯一能到达的入口。它把 slug 解析为分享记录，校验过期与项目归档状态，
然后一次返回整页所需的数据：

```jsonc
{
  "project": { "name", "description", "start", "end", "taskCount", "completedCount" },
  "states":  [{ "id", "name", "color", "category", "sortOrder", "taskCount" }],
  "members": [{ "name", "avatar": 1, "owner": true }],
  "tasks":   [{ "id", "title", "description", "stateId", "priority",
                "startDate", "dueDate",
                "labels": [{ "name", "color" }],
                "documents": [{ "title", "slug" }] }]
}
```

任务不携带负责人、创建者和任何用户 ID。`members[].avatar` 是该成员在这份列表中的序号，
不是文件名，也不是用户 ID；头像接口按同一序号取回图片，成员没有头像时字段缺席。
`documents[].slug` 只在文档当前有一条有效公开链接时出现。任务按开始日升序、同日按 `rank`
排序，一次最多返回 2,000 条未归档任务。

之所以是自定义接口而不是 PocketBase 内建规则：匿名请求要用 slug 换取另外五个集合的记录、
校验过期、裁剪掉用户身份与角色，还要为每篇关联文档反查 `doc_shares` 的有效性，这一串动作
超出 API Rules 能表达的范围。头像走代理而不是直接给出文件 URL，是因为 PocketBase 的文件
URL 必然带着用户记录 ID，代理让"团队只以名称和头像出现"这条规则没有例外。分享记录的读取
仍走 PocketBase 内建 CRUD，只有写入需要自定义接口来分配 slug。

## 10. 验收标准

- 任务可以设置可选开始日期；开始日晚于截止日时服务端拒绝，两端任一为空都合法。
- 历史任务在没有开始日期时行为不变，时间线按截止日当天呈现。
- 只有项目 Owner 能看到分享入口并发布、改期、撤销；Admin、Member、Viewer 调用接口被拒绝。
- 撤销后再次发布得到新的 slug，旧链接不可用。
- 过期、撤销、项目归档、项目删除四种情况返回相同的不可用响应。
- 匿名访问者在未登录、未安装任何客户端的情况下可完整浏览公开页面。
- 公开响应中不含任务负责人、成员邮箱、成员角色、任务创建者、活动日志与归档任务。
- 项目内新增、修改、完成任务后，访问者点击刷新即可看到最新状态，无需重新发布。
- 时间线覆盖项目日期跨度：跨多天的任务呈现为横跨的条带，并在覆盖的每一天可见；无日期
  任务归入 `Unscheduled`。
- 单日任务超过六条时折叠，展开后可见全部，收起后回到六条。
- 顶部概览的任务总数与各状态计数与项目实际未归档任务一致。
- 任务详情中，已公开文档跳转到其公开链接并可正常阅读；未公开文档不可点击并提示作者未公开。
