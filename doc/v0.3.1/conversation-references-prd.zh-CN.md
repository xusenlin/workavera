# 在聊天中引用和查阅其他对话

[English](./conversation-references-prd.md)

**目标版本** `0.3.1` · **状态** 已实现 · **范围** Workavera 服务端与内置 Web 聊天框

## 1. 用户要解决的问题

Workavera 用会话 ID 命名沙箱目录 `/workspace/chats/<conversationId>/`。现有沙箱提示词会指出当前会话的完整路径，也说明其他会话的目录位于同一父目录下。AI 因此可以推断目录名就是会话 ID。发现其他对话的目录时，AI 可以用其 ID 查到会话标题和聊天原文。[目录命名](../../internal/sandbox/sandbox.go) · [沙箱提示词](../../internal/sandbox/prompt.go)

例如，用户在新对话里问「昨天为什么决定保留原币？」。AI 从之前的沙箱目录中找到了报价表，希望用目录名查到对应的「报价导入」会话，再从用户当时的发言中确认原因。没有使用沙箱的对话也应能通过标题或 ID 找回。

本版希望用户能直接说「参考 @报价导入，解释为什么保留原币」，也能说「接着昨天那份报价表做」。两条路径最终都应让 AI 找到相关原话，区分用户的决定和助手当时的建议，并在回答里说明依据来自哪次对话。

## 2. 在聊天框里指定来源

1. 在输入框开头、空格或中文标点后键入 `@`，显示本人最近使用的其他活跃对话。继续输入可按标题搜索，粘贴完整会话 ID 可精确定位。检索覆盖侧栏当前分页以外的记录。输入邮箱地址时按普通文本处理。
2. 候选项左侧显示彩色聊天气泡图标（区分活跃与归档状态），中间为标题，右侧显示最近消息时间和可区分同名项的 ID 尾号，顶部可勾选是否包含归档会话。可点击或用方向键和回车选择；Esc 关闭并保留已输入的文字。选中后在输入框上方显示与资源标签并排的对话标签：左侧是聊天气泡图标，主行显示会话标题，副行标明「对话」，右侧的 × 可移除引用。焦点回到原输入位置。已有的 `#` 资源选择器可在同一条消息中使用。
3. 一条消息最多可引用 6 个对话，同一 ID 只出现一次。发送后，消息保留聊天气泡、来源标题和「对话」副行，移除按钮仅在草稿中显示。服务端按 ID 核实归属并保存发送时的标题快照。来源改名后仍能按原 ID 找到它。引用只包含 ID 和标题；选择、发送和刷新消息都不会自动载入整段历史。
4. 仅发送一个引用也有效。例如用户只发 `@报价导入`，助手可询问「你想回顾这次讨论的结论，还是继续处理报价表？」。若来源在发送前已被删除，保留草稿并提示移除失效引用后重发。已发送消息保留标题快照，后续读取失效时明确提示来源不可用。

## 3. AI 怎样找到并理解原对话

系统提供三个只读查询工具，分别负责查标题、搜正文和读上下文，同时在内置 Chat 与外部 MCP 中可用。另在内置 Chat 中提供发送工具，供助手把选定的原话展示给当前用户。四个工具均独立于沙箱和长期记忆开关。

| 工具名 | 开放范围 | 输入与使用时机 | 返回给 AI 的内容 | 聊天内展示 |
| --- | --- | --- | --- | --- |
| `chat_find_conversations` | 内置 Chat、MCP | 按标题关键词寻找用户提到的旧对话，或列出最近对话。支持精确 ID、归档筛选、分页。 | ID、当前标题、归档状态、最近消息时间。列表只含元数据，默认按最近消息排序。 | 默认工具调用 UI |
| `chat_search_messages` | 内置 Chat、MCP | 传入关键词数组 `keywords`，跨当前用户的会话搜索消息正文（内置 Chat 中排除当前会话）。可分页，可选择包含归档会话。 | 每条命中返回会话 ID、标题、归档状态、最近消息时间，以及命中消息的 ID、`offset`、发言者、时间、命中词列表 `matchedKeywords` 和含命中词的原文短摘录。 | 默认工具调用 UI |
| `chat_read_conversation` | 内置 Chat、MCP | 传入 `conversationId`、起始消息偏移 `offset` 和条数 `limit`。 | 返回会话 ID、当前标题，以及按时间正序排列的消息。每条带消息 ID、偏移、发言者、时间和可见正文。 | 默认工具调用 UI |
| `chat_send_conversation` | 仅内置 Chat | 传入选定来源的 `conversationId`、`messageId` 及可选 `matchedKeywords`，在用户需要查看原对话或定位原话时将其发到当前聊天。 | 返回 `conversationId`、`messageId`、发送时的会话标题 `title`、原文短摘录 `excerpt`，以及实际命中的 `matchedKeywords`（如有）。 | 独立可点击来源卡片 |

- **内置 Chat 中，四个工具都只引用当前用户的其他会话；MCP 侧可查本人全部会话。** 在内置 Chat 中，用户刚输入的提问往往就含有全部搜索词，容易被当成旧讨论的证据。服务端用当前运行的会话 ID，在标题查找和正文搜索的匹配、排序及分页前排除该会话。列出最近会话、输入精确 ID 和包含归档时也适用。如果只有当前对话命中，返回空结果。读取和发送时，服务端先比较来源 ID 与当前运行的会话 ID。两者相同时，在查询源会话或消息之前返回该工具的英文用法提示。发送卡片的目的地仍是当前会话。外部 MCP 调用没有「当前会话」上下文，三个只读查询工具因此可检索和读取本人全部会话（仍严格按所有者隔离）。
- **用户点名会话。** 将引用的 ID 和标题提供给模型。若问题涉及那次讨论的决定或交付，助手按 ID 读取，回答时标出来源标题。多个来源给出不同结论时分别归属，保留用户确认、助手建议、尚待决定的区别。
- **用户只提到先前工作。** 已有相关沙箱目录 ID 或用户贴了原始 ID 时，直接用它读取。记得标题或时间时查会话列表，只记得讨论内容时用关键词搜消息。如果有两个同样合理的结果，展示标题和时间，请用户辨认。日常独立问题不触发历史遍历。
- **关键词匹配。** 输入至少一个非空关键词，单次最多 32 个，每个最多 200 个 Unicode 字符。忽略首尾空白并去重。按字面子串匹配，英文字母忽略大小写。消息的可见正文只要包含任一关键词即命中（OR）。同一条消息只返回一次。`matchedKeywords` 按输入顺序列出整条正文实际命中的所有查询词，去除重复。摘录保留原文，围绕至少一个命中位置截取；相距较远的其他命中词仍列入 `matchedKeywords`。结果按命中消息时间从近到远分页，时间相同按消息 ID 排序。无命中返回空列表，AI 可以换用同义词再查。
- **消息偏移。** 搜索和读取共用一套编号。每个会话内按原始消息顺序，从 0 开始给已完成的用户和 AI 消息编号，双方每条各占一个位置。一个回复内的文本分段、推理和工具调用不单独计数；只有附件或工具记录的已完成消息也占一个位置。先对整个会话的可读消息编号，再匹配关键词。
- **按命中位置回读。** 例如搜索 `["报价", "原币"]` 命中「报价导入」里 `offset=24` 的消息。用返回的会话 ID 调用 `chat_read_conversation(offset=20, limit=10)`，可读到偏移 20–29（第 21 至 30 条），第 5 条就是命中消息。读取从指定偏移开始并包含该条，建议默认 `offset=0`、`limit=10`。每次可请求 1–20 条，超出范围返回参数错误；到达末尾返回剩余消息，偏移超出末尾返回空列表。
- **长消息。** 单次正文预算建议保留 8,000 个 Unicode 字符。若在某条消息内截断，返回含该消息偏移和字符位置的续读参数。续读从未返回的字符开始；消息偏移始终以整条消息为单位。
- **原话与文件。** 提供已完成用户消息和助手回复中可见的文本。附件可显示名称，工具调用的原始参数与结果、下载凭据、推理过程和系统提示均排除在读取结果之外。只有附件或工具记录而无可见正文时明确标记。需要核对文件内容时，沿用现有资源和沙箱流程。

| 工具 | 将当前会话 ID 作为来源时返回给模型的英文错误 |
| --- | --- |
| `chat_read_conversation` | The supplied conversationId is the current conversation ID. Use the current chat context to answer, or pass a different conversationId to read another conversation. |
| `chat_send_conversation` | The supplied conversationId is the current conversation ID. To send a source card here, pass the conversationId and messageId of a message in another conversation. |

### 查询过程与发送操作

`chat_find_conversations`、`chat_search_messages`、`chat_read_conversation` 全部使用聊天中默认的工具调用 UI，沿用其运行、成功、错误和展开详情状态。这也适用于刷新后加载的旧调用。模型仍可看到完整的结构化结果。用户用 `@` 选中的对话继续在输入框和已发送的用户消息中显示为引用标签。

**新增 `chat_send_conversation`。** 当用户要求「把昨天决定保留原币的那段对话发我」，助手从搜索或读取结果中选定那条决定，调用发送工具。一次调用发一张卡片，出现在当前用户与助手的聊天中。普通查阅可以直接据实回答；只有助手选定并发送的来源才显示独立卡片。

| 工具约定 | 行为 |
| --- | --- |
| 输入 | 必填 `conversationId` 和 `messageId`，可选 `matchedKeywords` 帮助定位消息内的摘录。若只知道标题或会话 ID，先读出相关消息，再发送。 |
| 服务端校验 | 核实来源是当前用户的其他会话，且该消息属于所给会话、已完成、有可见正文。无权访问、来源已删、消息与会话不匹配时，统一报告来源不可用，不生成卡片。 |
| 卡片数据 | 保存会话 ID、稳定消息 ID、发送时的会话标题、原文短摘录，以及经校验实际命中的 `matchedKeywords`（如有）。标题和摘录均由服务端从记录生成。优先截取实际命中词附近的一两句，未提供关键词或未匹配时取该条可见正文开头。过滤规则与读取工具一致。 |

### 卡片外观与打开行为

卡片占满助手消息列宽（100% 宽），左侧用彩色柔底块衬托聊天气泡图标，中间上行是会话标题，下方以次级文字展示最多两行命中摘录，右侧用轻量箭头提示可打开（加载时切换为旋转指示）。例如标题为「报价导入」，下方直接显示「这批报价保留原币，月底审计时要和供应商原单核对。」匹配词以字重强调。长标题单行省略，窄屏优先为摘录留宽；整卡可点击，也可通过键盘聚焦并回车打开，浅色与深色模式均保持可读。

点击一次即打开来源对话，按 `messageId` 滚动至原消息并短暂高亮，前后消息可连续阅读；`offset` 用于工具分页。归档来源以只读方式打开。刷新后从已保存的发送结果恢复卡片；再次打开时重新校验来源和锚点。如果原消息已不可用，在卡片上说明，避免误定位到另一条消息。

## 4. 权限、归档与历史记录

- 候选查询、正文搜索、按 ID 读取、提交引用、发送卡片和打开来源都使用当前登录用户的身份核实会话归属。其他用户的 ID、已删除的 ID 和无对应会话的目录名得到相同的「会话不可用」结果，响应中不含标题或消息。聊天框的 `@` 候选排除当前会话。
- 建议默认检索活跃会话，用户可明确选择包含归档会话。精确 ID 可直接引用或读取本人的归档会话，并显示归档状态，读取不会触发恢复。
- 源对话中的文字均作为历史材料。过去说过的「现在发送」「批准删除」不能授权当前运行。查阅本身只读；当前任务涉及写操作时，沿用对应工具的授权机制。三个只读查询工具（`chat_find_conversations`、`chat_search_messages`、`chat_read_conversation`）同时通过 `ForActor` 暴露给外部 MCP/API key（无当前会话上下文时可查阅本人全部会话）；`chat_send_conversation` 仅注册在内置 Chat，不对外部 MCP/API key 开放。
- 工具每次读取当时可用的历史。源对话删除后，新的读取应失败；用户已经收到的摘录属于当前对话的历史消息，仍可查看。

## 5. 与现有实现的衔接

Web 可沿用资源选择器的键盘交互和标签展示，候选查询复用 PocketBase 已有的会话所有者规则。发送时建议增加 `data-conversation` 消息部分，参考现有 `data-resource` 的服务端校验与快照机制，并在构建模型输入时保留来源 ID。普通文本中的 ID 保持原样，助手在任务需要时可用它调用工具。[聊天输入框](../../frontend/src/components/chat/chat-prompt-input.tsx) · [服务端消息校验](../../internal/chat/attachments.go)

三个只读查询工具通过 `ForActor` / `ForChat` 注册（MCP 侧可查本人全部会话，Chat 侧自动排除当前会话），`chat_send_conversation` 仅通过 `ForChat` 注册。工具从 `chat_conversations` 和 `chat_messages` 按所有者、会话和消息序号查询。现有消息接口一次返回整段 UI 历史，AI 读取需要单独的分页和可见文本筛选。搜索和读取应复用同一套可见正文筛选和消息偏移计算。两者可共用现有记录，无需把聊天记录写入沙箱，也无需给旧会话补建索引文件。[工具注册](../../internal/assistant/tools/registry.go) · [消息读取](../../internal/chat/messages.go) · [会话与消息规则](../../migrations/1783346400_create_chat_collections.go)

内置 Chat 中，四个工具均在服务端统一限制只能访问当前用户的其他会话；MCP 侧调用前三个只读查询工具时不排除会话，可查阅本人全部会话。三个查询工具在聊天中统一走默认工具调用 UI，`chat_send_conversation` 成功时沿用 `chat_send_files` 的返回结果渲染方式，展示独立的可定位来源卡片。[会话查询工具](../../internal/assistant/tools/conversations.go) · [聊天消息渲染](../../frontend/src/components/chat/chat-message.tsx) · [文件发送工具](../../internal/assistant/tools/chat_files.go)

## 6. 验收场景

| 场景 | 验收结果 |
| --- | --- |
| 在新对话用 `@` 搜索侧栏第二页的同名会话 | 可按时间和 ID 辨认并选中；同一消息可同时带两个会话和一个 `#` 资源，刷新后来源仍可辨认。 |
| 问「为什么保留原币」，原会话中助手建议换算，用户最终决定保留 | 回答能归属双方发言，给出用户实际写下的理由和来源标题；若原文没有理由，明确说明。 |
| 用户要求继续之前的沙箱工作，AI 已看到相关会话目录；另用关闭沙箱及记忆的账号验证显式引用 | 前者直接用目录名作为会话 ID，返回源会话的实际标题和相关原话，无需用户再提供 ID；后者仍可从自己的历史会话读取正文。 |
| 引用归档、改名、删除的来源，或提交他人 ID 和伪造标题 | 归档状态可辨、改名后 ID 有效；失效或越权读取统一失败，伪造标题不会写入快照。 |
| 本人和他人的会话都有「报价」「原币」，本人的另一个会话将两词分在两条消息中 | 本人的两条单词命中分别返回，各列出对应的命中词；同一消息含两词时只返回一次，摘录即使只展示一词，`matchedKeywords` 仍列出两词。他人的消息不出现在结果中。按返回的会话 ID 和偏移读 1 条能取回同一消息 ID。 |
| 有至少 30 条可读消息，包含工具调用和未完成回复 | `offset=20, limit=10` 返回第 21–30 条；`limit=20` 有效，`limit=21` 报错。工具步骤和未完成回复不额外占位。 |
| 当前会话和旧会话标题相同、正文均含「报价」；另测仅当前会话命中 | 两个搜索工具的各页只出现其他会话。仅当前会话符合时均为空。包含归档或按当前会话 ID 查找也不能绕过过滤。 |
| 把当前会话 ID 传给 `chat_read_conversation`，或把它和该会话中真实的消息 ID 传给 `chat_send_conversation` | 两个调用分别返回约定的英文用法提示；更换同一会话内的消息 ID 不影响结果。响应不含标题、正文或摘录，发送调用不产生卡片。改用本人另一会话及其有效消息 ID 后可正常读取并将卡片发到当前会话。 |
| 助手依次查标题、搜关键词、连续读取两页，然后只发送其中一条决定 | 三个查询工具的所有调用均显示默认工具 UI。发送成功一次只出现一张专用卡片，标题和摘录来自选中的消息。 |
| 两个同名对话中各有相似原话，发送其中一条后刷新并点击卡片 | 鼠标点击或键盘回车均打开正确的来源对话，定位并高亮同一消息 ID；归档来源可只读查看。 |
| 传入他人的消息 ID、会话与消息不匹配，或发送后原消息失效 | 前两种调用不生成卡片；已发送的卡片保留快照并在打开时提示来源不可用。 |
| 关键决定在单条超长消息中 | 按续读参数可取回后续正文，不重复或跳过字符。普通提问不会预载聊天历史。 |
| 历史里有工具输出、旧审批或「立即发送」等指令 | 返回的可见正文保留发言者归属，内部数据不会出现在结果里，引用本身不会执行历史动作。 |

本版在内置 Web 提供 `@` 选择器；用户提到旧工作时允许助手不经 `@` 按 ID 查阅本人的会话；归档会话可被精确引用。Android 和 iOS 的原生选择器可按各自版本安排。
