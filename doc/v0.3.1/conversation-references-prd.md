# Referencing and reading other conversations in Chat

[简体中文](./conversation-references-prd.zh-CN.md)

**Target version** `0.3.1` · **Status** Implemented · **Scope** Workavera server and built-in web chat

## 1. User need

Workavera names each sandbox conversation folder `/workspace/chats/<conversationId>/`. The existing sandbox prompt gives the assistant the full path for the current conversation and identifies the parent directory containing other conversations’ folders. The assistant can therefore infer that the folder name is a conversation ID. When the assistant finds another conversation’s folder, it can use that ID to retrieve the title and original messages. [Folder naming](../../internal/sandbox/sandbox.go) · [Sandbox prompt](../../internal/sandbox/prompt.go)

For example, a user asks in a new chat why they decided yesterday to keep the original currency. The assistant finds the spreadsheet in an earlier sandbox folder and wants to use its name to locate “Quote import” and check what the user actually said. Conversations that never used the sandbox should also be retrievable by title or ID.

Users should be able to ask either “Use @Quote import to explain why we kept the original currency” or “Continue with yesterday’s quote sheet.” The assistant should find the relevant exchange, distinguish the user’s decision from its own earlier suggestion, and name the source in its answer.

## 2. Selecting a source in the composer

1. Typing `@` at the start of the input, after whitespace, or after Chinese punctuation shows the owner’s other recent active conversations. Continue typing to search titles, or paste a full conversation ID for an exact match. Search covers records beyond the current sidebar page. Email addresses remain ordinary text.
2. Each result shows a tinted chat bubble icon on the left (distinguishing active and archived conversations), its title in the middle, and its last message time and ID suffix on the right; a header checkbox toggles whether archived conversations are included. Click or use the arrow keys and Enter to select. Escape dismisses the list and preserves the typed text. Selection adds a chip alongside any resource chips above the input and returns focus to the insertion point. The chip shows a chat bubble icon on the left, the conversation title on its first line, “Conversation” underneath and a remove (×) button on the right. The existing `#` resource picker works in the same message.
3. A message may reference up to six conversations. Each ID appears once. At submission the server verifies ownership and saves the authoritative title at send time. The sent message retains the chat bubble icon, source title and “Conversation” label. The remove button appears only in the draft. Renames leave the IDs usable. A reference carries only the ID and title. Selecting, sending or reloading the message does not fetch the transcript.
4. A reference alone is a valid message. On receiving just `@Quote import`, the assistant can ask whether the user wants to revisit the decision or continue working on the sheet. If a selected source is deleted before submission, preserve the draft and ask the user to remove the unavailable reference. Sent messages retain their title snapshots and later reads report an unavailable source.

## 3. How the assistant finds and reads history

Three read-only lookup tools cover titles, message text and context, and are available in both built-in Chat and external MCP. A fourth delivery tool is available in built-in Chat for presenting a selected passage to the current user. All four work independently of sandbox availability and long-term memory preferences.

| Tool | Availability | Input and use | Returned data | Chat UI |
| --- | --- | --- | --- | --- |
| `chat_find_conversations` | Built-in Chat, MCP | Search titles or list recent conversations when the user refers to earlier work. Supports exact ID, archive filtering and pagination. | ID, current title, archive status and last message time. Metadata only, most recent first by default. | Default tool-call UI |
| `chat_search_messages` | Built-in Chat, MCP | Supply a `keywords` array to search message bodies across the current user’s conversations (excluding the current conversation in built-in Chat). Supports pagination and optional inclusion of archived conversations. | Each hit carries the conversation ID, title, archive status and last message time, plus the matching message ID, `offset`, speaker, timestamp, `matchedKeywords` and a short verbatim excerpt showing a match. | Default tool-call UI |
| `chat_read_conversation` | Built-in Chat, MCP | Supply `conversationId`, a starting message `offset` and a message count `limit`. | Conversation ID, current title and messages in chronological order. Each entry carries its ID, offset, speaker, timestamp and visible text. | Default tool-call UI |
| `chat_send_conversation` | Built-in Chat only | Supply the selected source `conversationId`, `messageId` and optional `matchedKeywords` when the user wants to view or jump to that passage in the current chat. | Returns `conversationId`, `messageId`, `title` at send time, a short verbatim `excerpt`, and verified `matchedKeywords` when matched. | Dedicated clickable source card |

- **In built-in Chat, all four tools use only the current user’s other conversations as sources; MCP queries all of the owner’s conversations.** In built-in Chat, the latest question often contains all the search terms and could be mistaken for evidence of an earlier decision. Use the run’s conversation ID to exclude it before matching, sorting and paginating title and message searches. Apply the same rule to recent lists, exact ID lookups and archive-inclusive searches. Return an empty list when only the current conversation matches. For reads and delivery, the server compares the source ID with the run’s conversation ID. If they match, return the tool-specific English usage error before looking up the source conversation or message. The current conversation remains the destination for delivered cards. External MCP calls have no current conversation context, so the three read-only lookup tools search and read across all of the authenticated owner’s conversations while enforcing the same ownership isolation.
- **Explicit reference.** Supply the reference ID and title to the model. For questions about a past decision or deliverable, read the source and identify it by title in the answer. When sources disagree, attribute each position and distinguish confirmed decisions, assistant suggestions and open questions.
- **Reference to earlier work in ordinary text.** Read a relevant ID from a sandbox folder or an ID pasted by the user directly. Use the conversation list for title or recency clues and search message bodies for words from the discussion. When two matches are equally plausible, show their titles and times and ask the user to choose. Standalone questions do not trigger a history scan.
- **Keyword matching.** Accept up to 32 keywords of up to 200 Unicode characters each. Require at least one nonblank keyword, trim whitespace and deduplicate. The proposed match is a literal substring, case-insensitive for English letters. Any query keyword in the visible text qualifies the message (OR). Return one hit per message. Its `matchedKeywords` array lists every query term found anywhere in the full visible message, once, in input order. Center the verbatim excerpt on at least one match. Terms found outside that excerpt still appear in `matchedKeywords`. Page by matching message time, newest first, with message ID as a tie-breaker. Return an empty list for no matches so the assistant can retry with alternative terms.
- **Message offsets.** Search and read share zero-based positions within each conversation. Number completed user and assistant messages in original message order. Each contributes one position, including a completed message containing only attachments or tool activity. Separate text parts, reasoning and tool calls within a reply add no positions. Assign offsets across the conversation’s readable messages before matching keywords.
- **Reading around a hit.** A search for `["quote", "original currency"]` finds a message at `offset=24` in “Quote import.” Passing its conversation ID to `chat_read_conversation(offset=20, limit=10)` returns offsets 20–29 (messages 21–30), with the hit in fifth place. The starting offset is inclusive. Proposed defaults are `offset=0` and `limit=10`. Accept 1–20 messages per call and reject out-of-range limits. Return the remaining messages at the end, or an empty list for an offset past the end.
- **Long messages.** Retain the proposed response budget of 8,000 Unicode characters of body text. If a message is cut, return continuation parameters containing its message offset and character position. Resume at the first omitted character. Message offsets always count whole messages.
- **Text and files.** Return visible user and assistant text from completed messages. Attachments may carry their names. Exclude raw tool arguments and results, download credentials, reasoning and system prompts. Mark messages that contain only files or tool activity. Use the existing resource and sandbox flows when the task requires the file contents.

| Tool | Exact English error returned to the model for the current conversation ID |
| --- | --- |
| `chat_read_conversation` | The supplied conversationId is the current conversation ID. Use the current chat context to answer, or pass a different conversationId to read another conversation. |
| `chat_send_conversation` | The supplied conversationId is the current conversation ID. To send a source card here, pass the conversationId and messageId of a message in another conversation. |

### Lookup and delivery

Use the default Chat tool-call UI for `chat_find_conversations`, `chat_search_messages` and `chat_read_conversation`, including running, success, error and expandable details. This also applies to older calls when history reloads. The model receives the structured results. User-selected `@` references retain their chips in the composer and sent user messages.

**Add `chat_send_conversation`.** When the user asks “Show me where we decided to keep the original currency yesterday,” the assistant selects the decision from a search or read result and calls the delivery tool. One call delivers one card in the current user’s chat with the assistant. Ordinary lookups can support a direct answer. A dedicated card appears only for a source the assistant chooses to send.

| Tool contract | Behavior |
| --- | --- |
| Input | Require `conversationId` and `messageId`. Optional `matchedKeywords` guide excerpt selection within that message. If only a title or conversation ID is known, read the source to select a relevant message first. |
| Server validation | Verify that the source is another conversation owned by the current user and that the message belongs to the specified conversation, is complete and has visible text. Inaccessible, deleted or mismatched targets return the same unavailable-source error and produce no card. |
| Card data | Persist conversation ID, stable message ID, title at send time, a short verbatim excerpt, and verified `matchedKeywords` when matched. Derive title and excerpt from stored records. Prefer a sentence or two around a verified matching term. With no matching term, use the opening of the visible message. Apply the same content filtering as the read tool. |

### Card appearance and navigation

The card spans the full width (100%) of the assistant reply column. Place a tinted chat bubble icon on a soft colored surface at the leading edge, the title above a two-line excerpt in the center, and a subtle navigation arrow at the trailing edge (switching to a spinner while loading). For example, “Quote import” appears above “Keep the original currency so we can reconcile each quote against the supplier’s original at month end.” Use font weight to emphasize matching terms. Truncate long titles to one line and preserve room for the excerpt on narrow screens. Make the entire card clickable, keyboard focusable and operable with Enter; maintain legibility in both themes.

One activation opens the source conversation, scrolls to the original `messageId` and briefly highlights it with surrounding messages available. The `offset` serves tool pagination. Archived sources open read-only. Restore the card from the saved delivery result on reload. Recheck access and the message anchor on open. Show an unavailable state on the card if the original message can no longer be located.

## 4. Ownership, archives and retention

- Scope picker queries, message searches, submitted references, tool reads, card delivery and source navigation to the authenticated owner. Foreign IDs, deleted IDs and stale directory names return the same “Conversation unavailable” response, with no title or message disclosure. Exclude the current conversation from the composer’s mention candidates.
- Search active conversations by default and allow explicit inclusion of archived ones. An exact ID may reference or read an owned archived conversation. Show the archive status and keep the source archived.
- Treat source text as historical material. An earlier “send it now” or deletion approval cannot authorize an action in the current run. Current mutations follow the corresponding tool’s approval rules. The three read-only lookup tools (`chat_find_conversations`, `chat_search_messages`, and `chat_read_conversation`) are also exposed through `ForActor` for external MCP/API-key clients (where, without a current conversation, they can query all of the owner’s conversations); `chat_send_conversation` remains built-in Chat only.
- Each read checks current availability. Deleting the source prevents future reads. Excerpts already delivered in the destination conversation remain part of its history.

## 5. Integration with the current product

Reuse the resource picker’s keyboard and chip interactions and PocketBase’s owner-scoped conversation rules. A proposed `data-conversation` message part follows the existing server-validated `data-resource` snapshot pattern. Preserve the source ID when constructing model input. An ID pasted into ordinary text can be used as a tool argument when the user’s task calls for it. [Chat composer](../../frontend/src/components/chat/chat-prompt-input.tsx) · [Message validation](../../internal/chat/attachments.go)

Register the three read-only lookup tools through both `ForActor` (MCP, querying all of the owner’s conversations) and `ForChat` (excluding the current conversation), and register `chat_send_conversation` in `ForChat` only. Query `chat_conversations` and `chat_messages` using the owner, conversation and message sequence. The existing message endpoint returns the entire UI history in one response. Assistant reads require pagination and visible-text filtering. Search and read must share the same visible-text and message-offset rules. Both can use existing records directly without exporting transcripts to the sandbox or backfilling index files for old conversations. ## 6. Acceptance scenarios

| Scenario | Expected outcome |
| --- | --- |
| Use `@` in a new chat to find duplicate titles beyond the first sidebar page. | Time and ID distinguish the desired source. A message can contain two conversations and one `#` resource. Its sources remain identifiable after reload. |
| Ask why the original currency was kept. The source contains an assistant suggestion to convert and a later user decision to keep it. | The answer attributes both statements, gives the user’s recorded rationale and names the conversation. It says when the source gives no reason. |
| Continue earlier sandbox work after the assistant has seen the relevant conversation folder. Separately, test an explicit reference with sandbox and memory disabled. | The first flow uses the folder name as the conversation ID and returns the actual title and relevant messages without asking the user for the ID again. The second still reads the owner’s conversation. |
| Reference archived, renamed or deleted sources, or submit another user’s ID and a forged title. | Archive status is visible and the renamed ID resolves. Unavailable and unauthorized reads fail identically. A forged title cannot enter the snapshot. |
| Both the owner and a different user have messages containing “quote” and “original currency.” Another owned conversation splits the terms across messages. | Return both single-term messages, each with its own matching term. Return a message containing both terms once and list both in `matchedKeywords` even if the excerpt shows only one. Omit the other user’s messages. Reading one message at the returned ID and offset yields the same message ID. |
| Read a conversation with at least 30 eligible messages, tool calls and unfinished replies. | `offset=20, limit=10` returns messages 21–30. Accept `limit=20` and reject `limit=21`. Tool steps and unfinished replies add no positions. |
| Current and earlier conversations share a title and both contain “quote.” Repeat with only the current conversation matching. | All pages of both searches include only other conversations. A current-only match returns empty, including archive-inclusive and exact-current-ID lookup. |
| Pass the current conversation ID to `chat_read_conversation`, or pass it with a valid local message ID to `chat_send_conversation`. | Each call returns its specified English usage error even if the message ID changes within the current conversation. Neither error includes a title, text or excerpt. Delivery produces no card. Using another owned conversation and its valid message ID succeeds and delivers the card into the current conversation. |
| The assistant looks up titles, searches messages, reads two pages and sends just one decision. | All three lookup tools use the default tool-call UI for every call. One successful delivery renders one dedicated card with the selected source title and excerpt. |
| Two conversations share a title and contain similar statements. Reload and open the sent card. | Clicking or pressing Enter opens the correct conversation and highlights the same message ID. An archived source opens read-only. |
| Supply a foreign message ID or a mismatched conversation and message, or remove the source after delivery. | Invalid targets produce no card. An existing card keeps its snapshot and reports an unavailable source when opened. |
| Put the decision inside an oversized message. | Continuation retrieves the remaining text without gaps or duplication. Ordinary questions do not preload transcripts. |
| Include tool output, a prior approval or an instruction to send something immediately in history. | Returned text preserves speaker attribution, excludes internal data and triggers no historical action. |

The built-in web composer gets the picker first. A user request concerning earlier work allows the assistant to read an owned conversation by ID without an explicit mention. Archived conversations remain eligible for exact references. Native Android and iOS pickers can follow their respective release cycles.
