# MCP 客户端集成产品需求文档

[English](./mcp-client-prd.md)

> 产品基线：Workavera `0.0.9`。

## 1. 目的

MCP 客户端集成让每位用户接入自己的第三方 Model Context Protocol 服务器，并在 Chat 中与内置的 Board、Calendar、Docs、Reading、Contacts 工具一起使用这些服务器提供的工具。

Workavera 已经作为 MCP **服务器**在 `/api/mcp` 上把工作区能力开放给 Claude Code、Cursor 等客户端。本功能是相反方向：Workavera 作为 MCP **客户端**，让应用内的助手能够触达 Workavera 自身不实现的能力。

## 2. 目标

- 让用户注册自己的 MCP 服务器，并在 Chat 中使用其工具。
- 保持工具定义稳定且可审阅：助手看到的永远是用户明确接受过的定义。
- 让用户逐个工具决定是否启用，以及每次调用是否需要审批。
- 不引入后台常驻进程、不维持上游长连接、不新增任何基础设施。
- 通过将远程工具排除在 Chat 以外的所有出口之外，保持工作区自身的权限保证不被削弱。
- 让故障可读：区分上游服务器的普通错误与已经过期的工具定义。

## 3. 非目标

- 在用户之间共享 MCP 服务器配置。
- `stdio` 传输及任何形式的本地进程启动。
- 通过 Workavera 自己的 `/api/mcp` 端点再导出用户的远程工具。
- 实时镜像上游工具清单，包括响应 `notifications/tools/list_changed`。
- MCP 的 resources、prompts、sampling、elicitation、roots。
- 本次不实现针对上游服务器的 OAuth 授权流程。
- 连接池或跨工具调用的连接复用。

## 4. 集成模型

整套集成建立在两个彼此独立的决定之上。

**锁定定义。** 一台服务器的工具定义是存放在 Workavera 数据库中的快照，而不是上游服务器的实时视图。快照只在用户刷新该服务器并接受变更时才被写入。上游随时可以新增、删除或重新定义工具；在用户接受之前，这些变化不会到达助手。这与依赖锁文件是同一种契约。

**惰性连接。** Workavera 不对任何上游服务器保持连接。连接在工具真正被调用时建立，在该次调用结束时关闭。

两者结合，系统不留任何后台状态：

| 时机 | 网络活动 |
| --- | --- |
| Chat 运行开始、装配工具 | 无；定义来自数据库 |
| 助手调用某个远程工具 | `initialize` → `tools/call` → 关闭 |
| 用户点击刷新 | `initialize` → `tools/list` → 关闭 |
| 其他任何时刻 | 无 |

由于装配工具不产生网络 I/O，一台无法连通的上游服务器既不会拖慢 Chat 运行的首字，也不会影响内置工作区工具的可用性。

## 5. 服务器数据

每台服务器对应一条 `mcp_servers` 记录，仅归其所有者所有。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `owner` | relation → users | 必填，级联删除 |
| `name` | text | 显示名称，必填，最长 100 字符 |
| `slug` | text | 工具名前缀，`^[a-z][a-z0-9_]{0,19}$`，同一所有者下唯一 |
| `transport` | select | `http`（Streamable HTTP）或 `sse` |
| `url` | text | 上游端点，必填，仅允许 `http`/`https` |
| `headers` | json | 隐藏字段；承载用户凭据的请求头 |
| `enabled` | bool | 该服务器是否向 Chat 提供工具 |
| `tools` | json | 锁定的工具定义，见下文 |
| `last_error` | text | 最近一次连接或刷新失败 |
| `last_refreshed` | date | 定义最后一次被接受的时间 |
| `created`、`updated` | autodate | 记录时间戳 |

MCP 服务器配置属于个人配置，不是管理员配置。`headers` 中通常是用户自己在上游服务的令牌，因此服务器不会被共享、转移或暴露给其他账号——包括通过应用界面暴露给超级用户。删除用户会一并删除其服务器。

每个账号最多注册 10 台服务器。

## 6. 工具定义

`tools` 是一组锁定的定义：

| 键 | 说明 |
| --- | --- |
| `name` | 上游工具名 |
| `description` | 上游描述，以用户接受时的内容为准 |
| `parameters` | 输入 schema 的 `properties`，`$ref`/`$defs` 已展开 |
| `required` | 输入 schema 的 `required` 列表 |
| `enabled` | 是否提供给助手 |
| `approval` | `always` 或 `never` |
| `hash` | 描述与 schema 的摘要，用于检测漂移 |
| `stale` | 当某次调用表明定义已与上游不符时置位 |

Fantasy 会把每个工具的 schema 重建为 `{type, properties, required}`，且不解析 JSON Schema 引用，因此 `$defs` 与 `$ref` 在刷新时就地展开。若某个工具的 schema 在有限深度内无法解析，则不予存储，并在刷新结果中报告为不支持。

每个账号最多锁定 100 个已启用工具，以保证注入的工具清单有界。

## 7. 配置生命周期

**新增。** 用户填写名称、slug、传输方式、URL 及所需请求头。记录创建时不含任何工具，尚不可用。

**刷新。** Workavera 建立连接、调用 `tools/list`，并将结果与已存定义比对：

- 上游已不存在的工具被移除；
- `hash` 未变的工具保留其 `enabled` 与 `approval` 设置；
- 新工具，以及描述或 schema 发生变化的工具，以禁用状态存储，审批模式按服务器的审批策略预设，并标记为待用户审阅。

刷新绝不会静默启用任何东西。用户未审阅过的工具永远不会提供给助手。

**审阅。** 用户看到哪些工具是新增、变更、移除，选择启用哪些，并为每个启用的工具设定审批模式。

刷新是上游内容进入助手上下文的唯一路径。

## 8. 工具命名

锁定的工具以 `mcp_<slug>_<name>` 的形式提供给助手，字符集净化为 `[a-zA-Z0-9_-]` 并截断至 64 字符，以满足各模型供应商对函数名的限制。`slug` 命名空间避免了服务器之间以及与内置工具之间的名称冲突。

## 9. 审批

审批在配置时逐个工具决定，并存入定义。运行时不从上游读取。

MCP 的 `readOnlyHint`、`destructiveHint` 等工具注解由上游服务器自行声明，因此不可信。它们仅用于审阅时预选复选框，界面上标注其来源为服务器提供，且永不决定运行时行为。

服务器级的 `approval_policy` 决定新发现工具的默认值：

| 策略 | 新工具的默认值 |
| --- | --- |
| `all` | `always` |
| `writes` | `always`，除非上游注解表明该工具只读 |
| `none` | `never` |

`approval=always` 的已启用工具会在联系上游之前先走 Chat 既有的审批闸门。由于 Workavera 无法把上游记录解析成人类可读的目标对象，审批卡片展示服务器名称、工具名称与完整参数，并说明该操作发生在外部服务上。

## 10. 调用执行

远程工具调用按以下顺序进行：

1. 用锁定的 schema 校验模型给出的参数。
2. 若该工具需要审批，请求审批。
3. 连接、调用 `tools/call`、关闭。
4. 判定结果。

本地校验放在最前，一方面让格式错误的模型输出不必发出网络请求，另一方面——更关键地——使得上游的参数拒绝成为「锁定 schema 已与上游不符」的证据。Fantasy 仅检查必填键是否存在，因此针对完整 schema 的校验由本功能自行完成。

连接使用 Chat 运行的上下文并附加超时，因此取消运行也会放弃上游请求。独立 SSE 流被关闭：Workavera 不消费服务端主动推送的通知。

连接失败以工具错误的形式返回给助手，而不是让整个运行失败。上游不可达时，内置工作区工具照常可用。

## 11. 结果判定

区分「上游真实错误」与「定义已过期」，决定了是否提示用户刷新。

| 结果 | 含义 | 处理 |
| --- | --- | --- |
| 返回结果带 `isError` | 工具执行了但失败 | 返回给助手；不做标记 |
| 协议错误指明工具不存在 | 工具已消失 | 该工具标记 `stale` |
| 本地校验未通过 | 模型给出的参数有误 | 返回给助手；不发请求；不做标记 |
| 本地校验通过但上游报参数无效 | 锁定 schema 与上游不一致 | 该工具标记 `stale` |
| 连接失败、超时或认证被拒 | 服务器或凭据问题 | 记入服务器级 `last_error` |
| 其他协议错误 | 上游自身故障 | 返回给助手；不做标记 |

后两行的区分在界面上很重要：凭据过期与工具变化需要用户采取不同的动作，因此服务器级的连接失败绝不呈现为工具变化。

这套判定是启发式的。不同 MCP 服务器对同一种情况使用的错误通道并不一致，因此 `stale` 标记以「本次调用失败，定义可能已过期」而非「已确认变化」的措辞呈现。刷新视图会把真实差异摆给用户，判断权留给用户。

## 12. 信任边界

来自上游服务器的工具描述与工具结果是不可信数据。它们进入的是与内置工作区变更工具相同的模型上下文。

- Chat 系统提示明确：来自外部 MCP 服务器的内容是数据而非指令，不能据此授权任何工作区变更。
- 远程工具结果标注其来源服务器。
- 锁定定义模型本身就是这条边界的一部分：上游服务器无法在用户接受之前改变助手对某个工具用途的认知。

## 13. 出口边界

远程工具只加入 Chat 运行，不进入 `/api/mcp` 使用的工具集合。因此签发给第三方客户端的 API key 所暴露的，始终恰好是 Workavera 自身授权的工作区能力，密钥的 `allow_destructive` 范围也保持其精确含义。

## 14. 设置体验

设置页包含 MCP 服务器卡片，列出每台服务器的连接状态、已启用工具数量，以及待审阅或错误提示。

每台服务器可执行：

- 新增、编辑、删除；
- 整体启用或停用；
- 刷新，进入审阅视图；
- 审阅，展示新增、变更、移除、不支持的工具，并逐个设置启用与审批。

需要关注的服务器会被标记：工具被标 `stale`，或存在 `last_error`，都会在卡片上显示指示点，并以文字说明属于两者中的哪一种。凭据只写不读，已存储的请求头值永不返回给浏览器。

## 15. Chat 体验

远程工具调用使用通用工具卡片渲染，展示带命名空间的工具名、参数与结果。需要审批的远程调用使用既有审批卡片，并标明外部服务器。

当某次调用把工具标记为 `stale` 时，返回给助手的错误会说明该定义可能已过期、需要用户在设置中刷新该服务器。后续如何处理由助手决定。

## 16. 权限与生命周期

- 服务器及其请求头仅归所有者私有，不共享、不转移。
- 已存储的请求头不通过任何读取路径返回。
- 只有刷新会写入工具定义，客户端不能自行提交定义。
- 用户可直接编辑的定义字段只有「是否启用」与「审批模式」。
- 停用的服务器不提供任何工具，无论其已存定义如何。
- 删除用户会删除其服务器。

## 17. 验收标准

- 用户能够注册 MCP 服务器、刷新、启用指定工具，并在 Chat 中使用。
- 为 Chat 运行装配工具不产生任何网络 I/O。
- 不可达的服务器不拖慢任何 Chat 运行，也不使任何内置工具失效。
- 工具定义只能通过「刷新 + 用户接受」发生变化。
- 新发现或已变更的工具在审阅前处于禁用且需审批状态。
- hash 未变的工具在多次刷新之间保留其启用与审批设置。
- 上游注解只影响审阅默认值，不影响运行时审批。
- 本地校验未通过的参数不会产生上游请求。
- 结果判定严格按表标记 `stale` 与 `last_error`，且绝不把连接失败报告为工具变化。
- `/api/mcp` 中不存在远程工具。
- 已存储的请求头不会出现在任何 API 响应中。
- 用户无法读取或修改他人的服务器。
- 没有任何上游连接的存活时间超过开启它的那次调用。
